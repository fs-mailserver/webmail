## Korak 71 — ADR-071: Sigurnosna ažuriranja, ranjivosti i kontrola Docker imageova

Sada projektiramo **Container Security & Update Manager**, sustav koji će nadzirati sigurnost svih Webmail komponenti i kontrolirati njihova ažuriranja.

Budući da na istom dedicated serveru već rade Docker Mailserver, PostgreSQL, Redis i druge aplikacije, moramo spriječiti da automatska nadogradnja jedne komponente prekine rad ostalih.

### 2. Sigurnosne kontrole

| Kontrola | Predloženo pravilo |
|---|---|
| Docker imageovi | Fiksiranje na verziju i SHA256 digest |
| Python paketi | Zaključane verzije i provjera ranjivosti |
| Node.js paketi | Lockfile i dependency audit |
| SBOM | Generiranje za svako izdanje |
| Container scanning | Trivy ili ekvivalent |
| Secrets scanning | Sprječavanje objave tajni u Git |
| Image signing | Potpisivanje izgrađenih imageova |
| Provenance | Evidencija izvora i postupka izgradnje |
| CVE monitoring | Periodično praćenje novih ranjivosti |
| Produkcijsko ažuriranje | Isključivo nakon izričitog GO |

Ovo nadograđuje ADR-027 i ADR-029, u kojima smo već definirali GitHub Actions CI i obvezne testove prije prihvaćanja promjena.

### 3. Upravljanje ranjivostima

Predlažem početne rokove za obradu:

| Ozbiljnost | Ciljani rok |
|---|---|
| Kritična, aktivno iskorištavana | Procjena i zaštitne mjere unutar 24 sata |
| Kritična | Plan sanacije unutar 48 sati |
| Visoka | Sanacija u pravilu unutar 7 dana |
| Srednja | Unutar 30 dana |
| Niska | Redovni ciklus održavanja |

Ovo su **interni ciljevi**, a ne jamstvo da će svaka ranjivost biti riješena u tom vremenu.

Također nećemo blokirati cijeli razvoj samo zbog CVE zapisa u komponenti koja nije dosegljiva ili iskorištiva u našem sustavu. Potrebna je procjena stvarne izloženosti i dokumentirano prihvaćanje eventualnog rizika.

### 4. Posebno pravilo: produkcija se ne ažurira automatski

Automatsko stvaranje sigurnosnog Pull Requesta ne znači automatski merge ili deploy.

### 5. Što s postojećim Docker Mailserverom?

Njegova ažuriranja nećemo vezati uz redovne Webmail releaseove.

Mailserver, Dovecot, Postfix i ostali postojeći produkcijski servisi imaju zasebnu proceduru nadogradnje.

Time izbjegavamo da nova verzija Webmail frontenda slučajno pokrene rekreiranje mailserver kontejnera ili promjenu postojeće konfiguracije.
