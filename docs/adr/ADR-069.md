### 2. Što ćemo zaštititi?

| Podatak | Predložena zaštita |
|---|---|
| IMAP/SMTP pristupni podaci | Enkripcija na razini aplikacije |

Za šifriranje predlažem provjerene AEAD algoritme, primjerice AES-256-GCM, uz sigurno generiranje jedinstvenih nonce vrijednosti i verzioniranje formata šifriranih zapisa.

Nećemo razvijati vlastite kriptografske algoritme.

### 4. Rotacija ključeva

Rotaciju je potrebno podržati bez prekida rada aplikacije:

- Novi zapisi koriste novu verziju ključa.
- Stari podaci ostaju čitljivi tijekom kontroliranog prijelaza.
- Postojeći ključevi ne brišu se dok nisu provjereni svi podaci i backupi koji o njima ovise.
- Pristup ključevima ograničen je prema ulozi pojedinog servisa.
- Svaka rotacija i pristup osjetljivim administratorskim funkcijama evidentiraju se.

**Važno:** backup enkripcijski ključevi moraju imati zaseban plan oporavka. Gubitak jedine kopije ključa može učiniti backup trajno nečitljivim.

### 5. Posebno za postojeći Docker server

Budući da koristimo Docker Compose na vlastitom dedicated serveru, možemo birati između jednostavnijeg lokalnog upravljanja tajnama i zasebnog sustava za upravljanje ključevima.

Klasične `.env` datoteke nisu dovoljan sigurnosni mehanizam za sve tajne. Posebno ćemo izbjeći pohranu master ključeva u Git repozitorij, Docker image ili obične aplikacijske logove.
