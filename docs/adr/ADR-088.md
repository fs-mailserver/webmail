## Korak 88 — ADR-088: Webhookovi, događaji i integracije s drugim aplikacijama

Sada projektiramo **Webmail Event & Integration Hub** — sustav kojim će Webmail moći obavještavati druge aplikacije o događajima.

Primjerice, aplikacija Stay.hr može obrađivati rezervacijske e-mailove, dok drugi interni sustavi mogu primati obavijesti o novoj poruci, promjeni statusa ili administrativnom događaju.

Važno je da integracije ne dobiju automatski pristup cjelokupnom sadržaju e-mailova.

### 2. Vrste događaja

| Događaj | Primjena |
|---|---|
| `message.received` | Nova poruka u autoriziranom mailboxu |
| `message.sent` | Potvrđena SMTP predaja poruke |
| `message.flag_changed` | Promjena oznake ili pročitanosti |
| `mailbox.quota_warning` | Dosegnut prag zauzeća |
| `mailbox.created` | Novi mailbox |
| `user.deactivated` | Deaktivacija Webmail računa |
| `admin.operation.completed` | Dovršena administrativna operacija |
| `security.alert` | Sigurnosno upozorenje |
| `backup.failed` | Neuspjela sigurnosna kopija |

Kod `message.sent` moramo razlikovati prihvaćanje poruke od Postfixa i konačnu dostavu primatelju. SMTP prihvaćanje ne znači da je poruka dostavljena.

### 3. Privatnost podataka

Predlažem **minimalni webhook payload** prema zadanim postavkama.

<box border radius="lg" padding={3} gap={2}>
  <row align="center" justify="between">
    **Primjer `message.received`**
    <badge>Bez sadržaja poruke</badge>
  </row>
  <box background="surface-secondary" padding={3} radius="md">
    ```json
    {
      "event_id": "evt_example_001",
      "type": "message.received",
      "version": 1,
      "mailbox_id": "mbx_example_123",
      "message_ref": "msg_example_456"
    }
    ```
  </box>
  <caption>Ilustrativni payload. Identifikatori su primjeri, ne stvarni podaci.</caption>
</box>

Po zadanim postavkama webhook ne uključuje tijelo poruke, privitke, naslove ni popis primatelja.

Ako integracija treba sadržaj, mora dobiti posebnu dozvolu za određeni mailbox i vrste podataka. Koristit će autorizirani API iz ADR-087.

To nam omogućuje da Stay.hr, primjerice, dobije obavijest o rezervacijskom e-mailu bez otkrivanja pošte iz drugih mailboxa.

### 4. Pouzdanost isporuke

Webhook događaji trebaju imati sljedeća svojstva:

| Kontrola | Pravilo |
|---|---|
| Potpis | HMAC-SHA256 ili ekvivalent |
| Dostava | HTTPS |
| Identifikacija | Jedinstveni Event ID |
| Ponovni pokušaji | Exponential backoff |
| Idempotencija | Primatelj tolerira ponovljene događaje |
| Redoslijed | Sekvenca po resursu gdje je potrebna |
| Neuspješni događaji | Dead-letter evidencija |
| Audit | Evidencija pokušaja i rezultata |
| Tajne | Secrets Manager + rotacija |

Model isporuke bit će **at-least-once**, a ne lažno obećanje da se svaki webhook isporučuje točno jedanput.

Vanjske aplikacije moraju znati prepoznati već obrađene događaje.

### 5. Sigurnost webhook odredišta

Korisnici ne smiju moći registrirati proizvoljan URL kojim bi Webmail pristupao internim servisima ili privatnim mrežama.

Predlažem zaštitu od SSRF-a, validaciju HTTPS odredišta, kontrolu DNS rezolucije i preusmjeravanja te izolirane mrežne dozvole dispatcher servisa.

Također, webhook dispatcher ne smije dijeliti privilegije Mail Admin Agenta.

### 6. Upravljanje integracijama

U administratorskoj konzoli želimo vidjeti status svake integracije.

| Stavka | Primjer |
|---|---|
| Integracija | Stay.hr |
| Događaji | `message.received` |
| Mailboxi | Samo dodijeljeni |
| Status | Active / Paused |
| Posljednja isporuka | Vrijeme i rezultat |
| Retry queue | Broj događaja na čekanju |
| Tajna potpisa | Zaštićena, bez prikaza izvornog ključa |
