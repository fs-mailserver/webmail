## Korak 84 — ADR-084: Životni ciklus korisničkih računa i upravljanje pristupom

Sada definiramo kako ćemo upravljati korisnicima nakon njihova prvog prijavljivanja: promjenama uloga, privremenim blokadama, odlaskom zaposlenika i prijenosom pristupa zajedničkim mailboxima.

**Ključna odluka:** Webmail korisnički račun i Dovecot mailbox moraju imati neovisan životni ciklus.

To znači da deaktivacija Webmail korisnika ne smije automatski izbrisati njegovu e-mail adresu, poruke ili mailbox.

### 2. Statusi korisničkog računa

Predlažem sljedeće statuse:

| Status | Značenje |
|---|---|
| `invited` | Pozivnica poslana, aktivacija nije završena |
| `active` | Korisnik može pristupiti dodijeljenim mailboxima |
| `suspended` | Pristup privremeno blokiran |
| `deactivated` | Račun isključen iz redovne uporabe |
| `pending_deletion` | Pokrenut postupak kontroliranog brisanja računa |

Deaktivacija i suspenzija moraju odmah onemogućiti nove prijave i opozvati aktivne serverske sesije, API tokene i push pretplate.

Za PWA uređaje bez mrežne veze ne možemo jamčiti trenutačno fizičko uklanjanje prethodno spremljenih offline podataka. Zato ADR-024 i ADR-062 ostaju važni: ograničena offline pohrana, lokalna zaštita i čišćenje pri sljedećoj vezi.

### 3. Što se događa kada zaposlenik napusti tvrtku?

Primjerice, zaposlenik koristi osobni poslovni mailbox i ima ovlasti pristupa zajedničkom mailboxu `info@...`.

  <row align="center" gap={2}>
    <icon name="user-round-x" color="secondary"/>
    **Deaktivacija zaposlenika**
  </row>
  <list marker="number" connector="solid" gap={2}>
    <list-item>Blokira se njegov Webmail korisnički račun.</list-item>
    <list-item>Opozivaju se sesije, delegacije i pristup zajedničkim mailboxima.</list-item>
    <list-item>Osobni poslovni mailbox i njegova pošta ostaju sačuvani.</list-item>
    <list-item>Administrator zasebno odlučuje što će biti s mailboxom i poslovnim kontinuitetom.</list-item>
  </list>
</box>

**Važno:** ako zaposlenik još poznaje vlastitu Dovecot lozinku, sama deaktivacija Webmail računa ne sprječava pristup preko drugog IMAP klijenta.

Zato kod sigurnosnog ili zaposleničkog offboardinga moramo ponuditi zaseban, autoriziran postupak opoziva izravnog IMAP/SMTP pristupa, promjene vjerodajnica i drugih relevantnih pristupnih putova.

### 4. Prijenos pristupa mailboxu

Predlažem da sustav podržava administrativni prijenos pristupa, primjerice kada se promijeni osoba odgovorna za poslovnu adresu.

| Operacija | Pravilo |
|---|---|
| Dodavanje novog korisnika | Samo uz autorizaciju |
| Uklanjanje starog korisnika | Trenutačni opoziv Webmail pristupa |
| Promjena uloge | Ponovna evaluacija svih prava |
| Prijenos zajedničkog mailboxa | Nema kopiranja poruka; mijenjaju se ACL prava |
| Prijenos osobnog mailboxa | Posebna provjera pravne osnove i privatnosti |
| Promjena IMAP lozinke | Zasebna kontrolirana operacija Mail Admin Agenta |
| Brisanje mailboxa | Isključivo prema ADR-010 |

Administrator ne dobiva automatsko pravo čitanja stare korespondencije samo zato što deaktivira zaposlenika.

### 5. Pravila za posljednjeg Super Admina

Moramo spriječiti slučajno zaključavanje cijelog sustava.

Predlažem da Webmail ne dopušta deaktivaciju, brisanje ili uklanjanje Super Admin uloge **posljednjem aktivnom Super Admin korisniku**.

Također, Super Admin ne bi smio sam sebi odobriti osjetljivi Break-glass pristup tuđem mailboxu, što smo već definirali u ADR-066.
