## Korak 25 — ADR-027: GitHub, CI/CD i razvojna okolina

Sada definiramo kako ćemo razvijati i testirati projekt [fs-mailserver/webmail](https://github.com/fs-mailserver/webmail), bez ugrožavanja produkcijskog mailservera.

Zadržavamo ranije potvrđenu odluku da svi servisi u produkciji pripadaju postojećem Docker Compose stacku `/opt/stacks/mailserver/`.

To ne znači da razvoj i testiranje moraju koristiti produkcijske podatke.

### Predložena pravila razvoja

| Područje | Pravilo |
|---|---|
| `main` | Zaštićena glavna grana |
| Feature razvoj | Zasebne grane i Pull Requestovi |
| Claude Code | Programiranje i promjene koda |
| Copilot | GitHub operacije, PR-ovi i provjere |
| CI | Automatska provjera svakog PR-a |
| Testovi | Bez produkcijskih mailboxa i stvarnih tajni |
| Migracije baze | Alembic, s provjerom kompatibilnosti |
| Deployment | Samo nakon izričitog GO |
| Rollback | Obvezan postupak povratka za svako izdanje |

Važno: **spajanje PR-a ne smije automatski pokrenuti deployment**. Isto tako, CI ne smije imati produkcijske SSH ključeve ili mogućnost izmjene produkcijskog Compose stacka.

### Testiranje e-mail funkcionalnosti

Predlažem izolirani testni Docker Mailserver s testnim domenama i mailboxima. Na njemu ćemo provjeravati IMAP sinkronizaciju, slanje, brisanje, promjene zastavica, skice i oporavak nakon prekida veze.

Time ćemo moći provjeravati i zahtjevne scenarije bez pristupa stvarnim korisničkim porukama.
