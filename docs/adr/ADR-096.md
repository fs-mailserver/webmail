## Korak 96 — ADR-096: Design System i zajedničke UI komponente

Sada definiramo **Webmail Design System** — jedinstveni skup pravila, stilova i komponenti za Next.js aplikaciju, administratorsku konzolu i buduću Flutter aplikaciju.

Naš cilj je moderno sučelje brzine i preglednosti kakvu očekujemo od naprednih e-mail klijenata, ali bez nepotrebnog dupliciranja komponenti i CSS pravila.

### 2. Predloženi tehnološki izbor

| Sloj | Tehnologija |
|---|---|
| Web frontend | Next.js + TypeScript |
| Stilovi | Tailwind CSS |
| Pristupačne komponente | Radix UI primitives |
| Komponentni sustav | shadcn/ui pristup, lokalno održavane komponente |
| Ikone | Lucide |
| Dokumentacija komponenti | Storybook |
| Vizualni regresijski testovi | Playwright screenshot tests |
| Flutter | Material 3 uz prilagođene dizajnerske tokene |

Prednost ovog pristupa je što imamo kontrolu nad komponentama i ne ovisimo o zatvorenoj komercijalnoj UI biblioteci.

### 4. Zajedničke komponente

Predlažem biblioteku koja obuhvaća opće i specifične Webmail komponente.

| Opće komponente | Webmail komponente |
|---|---|
| Button, Input, Select | Message List |
| Dialog, Popover, Tooltip | Message Viewer |
| Table, Pagination | Mail Composer |
| Tabs, Navigation | Folder Tree |
| Toast, Alert | Attachment Viewer |
| Date Picker | Recipient Autocomplete |
| Command Palette | Thread View |
| Data Grid | Mailbox Switcher |

Svaka komponenta mora imati definirane interakcije, tipkovničko ponašanje, dostupna stanja, podršku za šest jezika i odgovarajuće testove pristupačnosti.

### 5. Responsive i prilagodljivi raspored

ADR-023 već predviđa Webmail s tri panela.

Predlažem:

| Uređaj | Raspored |
|---|---|
| Desktop | Tri panela — mape, poruke, sadržaj |
| Tablet | Dva panela, prema širini |
| Mobitel | Jedan aktivni prikaz |
| Veliki monitor | Prilagodljive širine panela |

Korisnik može prilagođavati širinu panela, gustoću prikaza i veličinu teksta. Postavke se čuvaju u PostgreSQL-u prema korisničkom profilu.

### 6. Održavanje Design Systema

Predlažem da Storybook bude razvojni katalog komponenti s primjerima normalnih, praznih, učitavajućih i pogrešnih stanja.

CI treba provjeravati TypeScript, testove, pristupačnost i vizualne regresije.

Time izbjegavamo situaciju da promjena jedne komponente nenamjerno pokvari Inbox, Composer i administratorsku konzolu.
