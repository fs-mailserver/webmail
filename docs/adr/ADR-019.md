## Korak 17 — ADR-019: Backup, retencija i oporavak

Budući da već koristiš dedicated server s RAID1 diskovima i postojećom PostgreSQL infrastrukturom, predlažem integraciju Webmaila u postojeći backup sustav, bez pokretanja novog backup servisa.

**Važno:** RAID1 štiti od otkaza jednog diska, ali nije zamjena za backup.

### Što moramo zaštititi?

| Podaci | Strategija |
|---|---|
| Dovecot Maildir | Primarni backup svih mailboxa |
| `webmail_db` | PostgreSQL backup i mogućnost obnove |
| `.eml` kopije | Backup ili ponovna izgradnja iz Dovecota |
| Privitci | Backup datoteka i provjera SHA-256 |
| AI konfiguracija | Backup postavki bez izlaganja ključeva |
| Korisnici i prava | Obvezan backup |
| Audit logovi | Zasebna retencija |
| Secrets | Šifrirani backup, odvojen od podataka |

Za početnu strategiju predlažem i sljedeća pravila: backupi moraju imati barem jednu kopiju izvan dedicated servera, restore se mora moći izvesti bez produkcijskog prekida, a brisanje mailboxa prema ADR-010 dopušteno je tek nakon provjere odgovarajuće sigurnosne kopije.

Važno je razlikovati **trajno brisanje aktivnog mailboxa** od retencije njegovih prethodnih backup kopija. Ako zahtjev za brisanje obuhvaća i sve backup kopije, potreban je zaseban postupak prema definiranoj politici zadržavanja.
