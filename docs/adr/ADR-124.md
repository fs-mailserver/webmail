## Korak 124 — ADR-124: Struktura monorepa i odgovornosti razvojnih agenata

Sada definiramo kako ćemo organizirati izvorni kod novog Webmaila.

Cilj je imati **jedan GitHub repozitorij**, ali jasno odvojene Next.js, FastAPI, Celery i infrastrukturne module.

To će nam omogućiti paralelan rad Claude Codea, Copilot agenta i Codexa bez nepotrebnih sukoba.

### 3. Podjela odgovornosti između modula

| Modul | Odgovornost |
|---|---|
| `apps/web` | UI, navigacija, lokalizacija i korisničke interakcije |
| `apps/api` | HTTP/WebSocket sučelje i provjera pristupa |
| `apps/worker` | Pozadinska obrada, IMAP sync i scheduler |
| `packages/backend` | Zajednička Python poslovna logika |
| `packages/ui` | React komponente i Design System |
| `packages/api-client` | Tipizirani TypeScript API klijent |
| `migrations` | Verzije PostgreSQL sheme |
| `infra` | Docker konfiguracija i operativni alati |
| `docs` | ADR-ovi, runbookovi i tehnička dokumentacija |

Za budući Flutter klijent neće trebati duplicirati FastAPI backend. Koristit će isti autorizirani API, uz vlastitu mobilnu implementaciju sučelja.

### 4. API kao ugovor između frontenda i backenda

Predlažem model **API-first**.

FastAPI definira OpenAPI specifikaciju, a frontend koristi generirani TypeScript klijent.

### 5. Pravila razvoja za agente

Ovdje zadržavamo već dogovorenu podjelu rada.

| Agent | Primarna odgovornost |
|---|---|
| **Claude Code** | Python, Next.js, migracije i testovi |
| **Copilot agent** | GitHub, grane, PR-ovi, oznake i kontrole repozitorija |
| **Codex** | Neovisna revizija, analiza i tehnička dijagnostika |

Svaki agent dobiva precizno definiran zadatak i dopušteni opseg datoteka.

`AGENTS.md` sadrži obvezna pravila o sigurnosti, testiranju, zabrani produkcijskih promjena i korištenju odgovarajućih ADR-ova.

### 6. Zaštita repozitorija

Predlažem:

| Kontrola | Politika |
|---|---|
| `main` | Zaštićena grana |
| PR review | Obvezan prije mergea |
| CI | Typecheck, lint, unit, integration i security |
| Migracije | Zasebna revizija promjena sheme |
| Tajne | Zabranjene u Git repozitoriju |
| Docker | Bez produkcijskih vjerodajnica u developmentu |
| Release | Verzije i changelog |
| Deployment | Nikada automatski bez GO |

Promjene migracija, autorizacije i Mail Admin Agenta moraju imati strožu reviziju od običnih UI promjena.
