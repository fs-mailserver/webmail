## Korak 24 — ADR-026: Monitoring, logiranje i nadzor sustava

Sada definiramo kako ćemo nadzirati novi Webmail, IMAP sinkronizaciju, AI workere, PostgreSQL i Docker Mailserver.

Cilj je da sustav automatski otkriva probleme i da administrator može vidjeti što ne radi, bez ručnog pregledavanja Docker logova.

### Što ćemo nadzirati?

| Komponenta | Metrike |
|---|---|
| IMAP Worker | Zadnja uspješna sinkronizacija, broj pogrešaka, zaostatak |
| FastAPI | Latencija, HTTP 5xx, aktivne sesije |
| WebSocket | Aktivne veze, reconnect, propušteni događaji |
| AI Worker | Broj zadataka, pogreške, tokeni i troškovi |
| Document Worker | Red čekanja, trajanje ekstrakcije, neuspjeli dokumenti |
| Redis | Memorija, dostupnost i stanje redova |
| PostgreSQL | Veze, upiti, veličina baze, prostor |
| Dovecot/Postfix | Dostupnost IMAP/SMTP servisa |

### Pravila logiranja

- Strukturirani JSON logovi s `request_id` i `job_id`.
- Bez zapisivanja lozinki, tokena, API ključeva ili sadržaja e-mailova.
- Odvojeni audit logovi za administrativne operacije.
- Health check za svaki novi kontejner.
- Upozorenja kada sinkronizacija stane ili se zadaci gomilaju.

Posebno bih dodao **Webmail Admin Health Dashboard**, kako bi Super Admin mogao vidjeti stanje sustava bez otvaranja Grafane.
