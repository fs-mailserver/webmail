## Korak 106 — ADR-106: Povezani Nextcloud računi, tokeni i sigurno prekidanje veze

Sada projektiramo **Connected Account Manager**, modul koji upravlja povezivanjem osobnih Nextcloud računa s Webmailom.

### 2. Povezivanje osobnog računa

Predlažem da korisnik u Webmailu odabere „Poveži Nextcloud”, nakon čega prolazi kroz podržani Nextcloud postupak autorizacije.

Webmail čuva izdanu vjerodajnicu, a ne glavnu lozinku korisnika. Lozinka ili token ne pojavljuju se u Next.js aplikacijskom stanju, lokalnoj pohrani preglednika ili logovima.

| Kontrola | Pravilo |
|---|---|
| Povezivanje | Nextcloud Login Flow v2, ako je dostupan |
| Vjerodajnica | Šifrirana, isključivo na backendu |
| Identitet | Povezivanje s točno jednim Webmail korisnikom |
| Dopušteni serveri | Administratorom odobrena lista Nextcloud instanci |
| TLS | Obvezna provjera certifikata |
| API pristup | Backend, nikada izravno iz preglednika s tokenom |
| Ponovno povezivanje | Nova autorizacija, bez otkrivanja stare vjerodajnice |
| Neispravna veza | Status „Potrebno ponovno povezivanje” |

Važna tehnička razlika: Nextcloud Login Flow v2 ne treba tretirati kao klasičan OAuth sustav s granularnim scopeovima. Izdana aplikacijska vjerodajnica može imati široka prava samog Nextcloud korisnika. Zato na backendu moramo ograničiti **koje operacije Webmail smije izvršavati**, čak i kada Nextcloud vjerodajnica tehnički dopušta više.

### 3. Sinkronizacija metapodataka

Ne želimo duplicirati sve osobne Nextcloud datoteke u PostgreSQL-u.

Predlažem dohvat strukture mapa i osnovnih metapodataka na zahtjev, s kratkotrajnim cacheom.

| Podatak | Ponašanje |
|---|---|
| Naziv i putanja datoteke | Dohvat preko WebDAV-a |
| Veličina i MIME tip | Metapodaci |
| Datum izmjene | Metapodaci |
| Nextcloud file ID | Stabilna referenca gdje je dostupna |
| Sadržaj datoteke | Dohvat samo kad je potreban |
| Povijest verzija | Ostaje u Nextcloudu |
| Webmail share status | Lokalni zapis uz provjeru Nextclouda |

Promjena datoteke ili ovlasti u Nextcloudu ne smije omogućiti korištenje zastarjelih prava iz Webmail cachea.

**Važno:** brisanje tokena iz Webmaila i stvarni opoziv u Nextcloudu nisu isto. Ako API opoziv ne uspije, veza se odmah blokira u Webmailu, a korisniku i administratoru prikazuje se da aplikacijsku vjerodajnicu još treba opozvati u Nextcloudu.

### 5. Što se događa pri prekidanju veze?

| Podatak ili funkcija | Postupak |
|---|---|
| Osobna pristupna vjerodajnica | Opoziv gdje je podržan i sigurno brisanje lokalne kopije |
| Lokalni cache metapodataka | Inval idacija i uklanjanje prema politici retencije |
| Osobne Nextcloud datoteke | Ne brišu se |
| Već poslani e-mailovi | Ostaju u Dovecotu |
| Aktivne javne poveznice | Zasebna provjera i opoziv prema odabranom pravilu |
| Servisna pohrana velikih privitaka | Ostaje odvojena od osobnog računa |
| Audit | Čuva se prema ADR-067 |

Posebno moramo riješiti slučaj kada korisnik u Webmailu podijeli osobnu Nextcloud datoteku, a zatim prekine povezivanje računa.

Takva poveznica može ostati aktivna u Nextcloudu čak i nakon prekidanja veze. Zato za Webmailom kreirana dijeljenja moramo imati jasno pravilo opoziva.

### 6. Administratorska kontrola i sigurnost

Predlažem da administratorska konzola prikazuje status integracija, ali nikada njihove pristupne tokene.

Administrator može vidjeti broj aktivnih veza, vrijeme posljednje uspješne provjere i sigurnosna upozorenja. Ne može automatski pregledavati osobne Nextcloud datoteke drugih korisnika.

Također uvodimo:

- Ograničenje na odobrene Nextcloud instance, uz zaštitu od SSRF-a i preusmjeravanja na nedopuštena odredišta.
- Šifriranje vjerodajnica prema ADR-069.
- Trenutačnu blokadu zahtjeva nakon opoziva pristupa.
- Evidenciju povezivanja, prekidanja veze i sigurnosnih pogrešaka.
- Izolaciju korisničkih i servisnih vjerodajnica.

Prije implementacije provjerit ćemo kompatibilnost sa stvarno instaliranom verzijom Nextclouda.
