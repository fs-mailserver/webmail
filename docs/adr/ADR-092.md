### 4. Dijagnostika bez otkrivanja privatnih podataka

Za tehničku podršku korisni su podaci poput verzije aplikacije, vrste preglednika, trajanja API zahtjeva, šifre pogreške i identifikatora korelacije.

Ali po zadanim postavkama ne smijemo prikupljati:

- Tijela e-mailova i privitke.
- Lozinke, API tokene i sjedničke kolačiće.
- Privatne ključeve ili MFA tajne.
- Cjelokupne IMAP/SMTP transkripte.
- Sadržaj korisnikovih kontakata.

Za slanje dodatnih dijagnostičkih podataka ili snimke zaslona potrebno je korisniku unaprijed prikazati što se šalje i zatražiti potvrdu. Priložene snimke mogu sadržavati osobne podatke pa moraju imati ograničen pristup.

### 5. Životni ciklus ticketa

| Status | Značenje |
|---|---|
| `open` | Zahtjev je zaprimljen |
| `triaged` | Kategoriziran i dodijeljen |
| `in_progress` | Podrška radi na problemu |
| `waiting_user` | Čeka odgovor korisnika |
| `resolved` | Predloženo rješenje |
| `closed` | Zahtjev je zaključen |

Korisnik vidi vlastite zahtjeve, a administratori samo one za koje imaju odgovarajuće ovlasti.

Pristup ticketu ne daje automatski pristup mailboxu na koji se problem odnosi.

### 6. Povezivanje s GitHubom

Kada korisnik prijavi stvarnu softversku grešku, korisno je otvoriti GitHub Issue za razvojni tim.

Ali GitHub Issue ne smije sadržavati privatnu korespondenciju, korisničke tajne ili neobrađene dijagnostičke zapise.

Predlažem da se iz support ticketa pripremi **sanitizirani tehnički sažetak**, koji se tek nakon pregleda može poslati u GitHub.

Time ostaje jasno razdvojeno:

- **Support ticket:** privatna komunikacija s korisnikom.
- **GitHub Issue:** tehnički zadatak za razvoj.

Za GitHub operacije i dalje zadržavamo zasebnu ulogu Copilot agenta, dok Claude Code radi promjene aplikacijskog koda.
