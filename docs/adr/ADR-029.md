## Korak 27 — ADR-029: Strategija testiranja i kriteriji prihvaćanja

Prije nego što krenemo s implementacijom, definirajmo kako ćemo dokazati da Webmail radi ispravno i da ne ugrožava postojeći Docker Mailserver.

Predlažem četiri razine testiranja.

| Razina | Što testiramo | Alat |
|---|---|---|
| Unit | Poslovna logika, prava, MIME parser, AI adapteri | Pytest, Vitest |
| Integration | PostgreSQL, Redis, IMAP, SMTP, Celery | Pytest + testni Docker stack |
| E2E | Prijava, Inbox, slanje, skice, administracija | Playwright |
| Security | Autorizacija, CSRF, HTML mail, privitci, ovisnosti | Sigurnosni testovi i skeneri |

### Pravila za GitHub CI

Svaki Pull Request mora proći obvezne provjere prije spajanja u `main`. Neuspjeli testovi blokiraju merge, a produkcijski deployment nije dio CI postupka.

Predlažem da razlikujemo brze provjere svakog PR-a i opsežnije testove koji se pokreću prije izdavanja verzije.
