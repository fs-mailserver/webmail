### 3. Sigurnosna pravila

| Funkcionalnost | Predloženo ponašanje |
|---|---|
| Registracija uređaja | Vezana uz autentificiranu sesiju |
| Push tokeni | Zaštićeni, nikada prikazani korisniku |
| Više uređaja | Dopušteno |
| Odjava uređaja | Opoziv server-side sesije |
| Push nakon odjave | Pretplata se deaktivira na backendu |
| Izgubljeni uređaj | Udaljena odjava |
| Promjena lozinke | Mogućnost odjave svih ostalih sesija |
| MFA promjene | Ponovna autentifikacija |
| Sigurnosni audit | Evidencija prijave i opoziva sesije |

**Važno:** udaljena odjava pouzdano blokira buduće API zahtjeve i nove Push obavijesti, ali ne može jamčiti trenutno fizičko brisanje svih podataka koji su već spremljeni offline na uređaju.

Zbog ADR-024, pri sljedećem povezivanju PWA mora ukloniti offline podatke opozvane sesije. Lokalni podaci također trebaju imati rok valjanosti i biti zaštićeni u najvećoj mjeri koju platforma dopušta.

### 4. Razlika između uređaja, sesije i Push pretplate

Jedan fizički uređaj može imati više preglednika i više sesija.

Zato u PostgreSQL-u trebamo odvojeno voditi:

| Entitet | Namjena |
|---|---|
| `devices` | Korisnički prepoznat uređaj ili instalacija |
| `sessions` | Autentificirane prijave |
| `push_subscriptions` | Web Push/FCM odredišta |
| `device_preferences` | Postavke obavijesti po uređaju |

Nećemo se oslanjati na agresivno fingerprintiranje uređaja. Identitet uređaja temeljit će se na registraciji pojedine instalacije i odgovarajućim sesijama.
