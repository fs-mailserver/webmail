## Korak 19 — ADR-021: Docker mreža, Traefik i izolacija servisa

Budući da smo odabrali jedinstveni Docker Compose unutar `/opt/stacks/mailserver/`, sada trebamo definirati koji će kontejneri biti dostupni internetu, a koji isključivo interno.

**Preporučujem da samo Traefik bude javna ulazna točka za Webmail.** SMTP i IMAP zadržavaju svoje postojeće izravno izložene portove.

### Sigurnosna pravila

| Komponenta | Pristup |
|---|---|
| Traefik | Javni HTTPS 443 |
| Next.js | Samo preko Traefika |
| FastAPI | Samo preko Traefika ili internog proxyja |
| Redis | Interni servisi, bez javnog porta |
| PostgreSQL | Samo autorizirani backend i workeri |
| AI Worker | Interno, izlazni HTTPS prema AI API-jima |
| Document Worker | Izoliran, bez nepotrebnog mrežnog pristupa |
| IMAP Worker | Dovecot IMAP i potrebne interne usluge |
| Mail Admin Agent | Samo autorizirane interne administrativne operacije |

Za `mail-admin-agent` predviđam ograničen skup operacija i zasebnu autentifikaciju između servisa. Nećemo javnom FastAPI backendu dati neograničen pristup Docker socketu.

Također, Docker mrežna izolacija sama po sebi nije dovoljna sigurnosna granica za obradu zlonamjernih privitaka. Document Worker treba imati dodatna ograničenja procesa, resursa i datotečnog sustava.
