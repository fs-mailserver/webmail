## Korak 32 — ADR-032: Paralelna IMAP sinkronizacija i raspodjela workera

Sada trebamo definirati kako će Webmail obrađivati više mailboxa istodobno, a da ne preoptereti Dovecot ili PostgreSQL.

U početnom `SPEC.md` predviđen je asinkroni IMAP IDLE worker. Proširit ćemo ga sustavom za raspodjelu i kontrolu zadataka.

### Ključna pravila

| Područje | Predloženo ponašanje |
|---|---|
| Paralelizam | Asinkroni pool konekcija s podesivim limitima |
| Raspodjela | Mailboxi se dodjeljuju dostupnim workerima |
| Zaključavanje | Samo jedan aktivni reconciliation posao po mapi |
| Lease | Automatsko preuzimanje posla ako worker otkaže |
| Prioritet | Nove poruke i korisničke radnje imaju prednost |
| Backpressure | Smanjenje paralelizma pri opterećenju |
| Reconnect | Exponential backoff s nasumičnim odstupanjem |
| Monitoring | Broj konekcija, zaostatak i vrijeme sinkronizacije |

Zaštita od paralelne obrade mora biti u PostgreSQL-u, a ne samo u Redis lockovima. Koristit ćemo lease s ograničenim trajanjem, fencing token i uvjetno potvrđivanje checkpointa, kako worker koji je izgubio lease ne bi mogao prepisati novije stanje.

### Početni kapaciteti

Predlažem da početne granice budu konfigurabilne, a ne tvrdo zapisane u kodu.

Primjer početnih vrijednosti za testiranje:

| Parametar | Početna vrijednost |
|---|---:|
| IMAP konekcije ukupno | 20 |
| Konekcije po mailboxu | 2 |
| Paralelni reconciliation zadaci | 4 |
| Timeout IMAP operacije | 30 sekundi |
| Reconnect backoff | 2–120 sekundi |
| Periodična provjera | Svakih 15 minuta |

To nisu potvrđeni kapaciteti tvog servera; potrebno ih je uskladiti sa stvarnom Dovecot konfiguracijom i rezultatima load testova.
