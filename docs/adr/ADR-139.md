## Korak 139 — ADR-139: Upravljanje domenama, mailboxima, aliasima i kvotama

Sada detaljno projektiramo **Mail Domain & Mailbox Management**, administrativni modul kojim ćemo upravljati poštanskom infrastrukturom kroz Webmail Admin Console.

Cilj je da Super Admin i ovlašteni domenski administratori mogu obavljati redovne administrativne zadatke bez ručnog pristupa Docker kontejnerima.

Pritom zadržavamo postojeći docker-mailserver, bez uvođenja drugog mailservera.

### 2. Administracija domena

Predlažem zaseban prikaz svih domena za koje je mailserver konfiguriran.

| Polje | Opis |
|---|---|
| Domena | Primjerice `example.com` |
| Status | Aktivna, suspendirana, zahtijeva provjeru |
| Mailboxi | Broj aktivnih računa |
| Aliasi | Broj konfiguriranih aliasa |
| Kvote | Zadane i posebne vrijednosti |
| DNS | Status MX, SPF, DKIM, DMARC provjere |
| Administratori | Ovlašteni domenski administratori |

Dodavanje domene u Webmail konfiguraciju nije automatska potvrda da su svi DNS zapisi ispravni.

DNS provjere iz ADR-041 i ADR-042 zasebno prikazuju stanje i daju upute za eventualne vanjske promjene.

### 3. Upravljanje mailboxima

Predlažem sljedeće operacije:

| Operacija | Kontrola |
|---|---|
| Kreiranje mailboxa | RBAC + Dry Run |
| Promjena kvote | RBAC + provjera dopuštenih granica |
| Resetiranje mail lozinke | Step-up MFA + sigurni kanal |
| Suspenzija mailboxa | Step-up MFA + potvrda učinka |
| Ponovna aktivacija | RBAC + provjera konfiguracije |
| Promjena administratorskih prava | Posebno odobrenje |
| Trajno brisanje mailboxa | Izričita potvrda, backup, Legal Hold i visoki rizik |

Prilikom kreiranja mailboxa trebamo jasno razdvojiti:

- stvarni Dovecot/Postfix mailbox,
- Webmail korisnički identitet,
- autorizirane veze korisnika s mailboxom.

Jedan mailbox može biti zajednički, a jedan Webmail korisnik može imati pristup većem broju mailboxa.

### 4. Upravljanje aliasima

Prema ADR-044 podržavamo pojedinačne aliase, prosljeđivanja i catch-all, ali catch-all i vanjsko prosljeđivanje ostaju isključeni prema zadanim postavkama.

| Vrsta | Primjer | Pravilo |
|---|---|---|
| Interni alias | `info@example.com` → mailbox | Dopušten uz provjeru |
| Višestruki primatelji | `sales@example.com` → više mailboxa | Provjera svih odredišta |
| Vanjski forwarding | Domena → vanjski primatelj | Dodatno odobrenje |
| Catch-all | Sve nepoznate adrese → odredište | Zadano isključeno |

Prije primjene aliasa moramo provjeriti cikluse prosljeđivanja, nepostojeća odredišta i potencijalno opasne konfiguracije.

### 5. Upravljanje kvotama

Prema ADR-078 definiramo zadane kvote po domeni, iznimke po mailboxu i upozorenja na 80 %, 90 % i 95 % iskorištenosti.

| Actual State | Provjereno stanje u docker-mailserveru |

### 7. Sigurnosna i infrastrukturna ograničenja

Administrativne operacije moraju poštovati:

| Kontrola | Pravilo |
|---|---|
| Domenski RBAC | Admin mijenja samo dopuštene domene |
| Step-up MFA | Za osjetljive promjene |
| Dry Run | Prije promjene mailserver konfiguracije |
| Idempotencija | Jedna logička promjena po zahtjevu |
| Audit | Tko, što, kada i rezultat |
| Docker pristup | Samo izolirani Agent |
| Backup | Obvezna provjera za destruktivne zahvate |
| Legal Hold | Blokira nedopušteno brisanje |
| Rollback | Planiran po vrsti promjene |

Posebno treba testirati kompatibilnost s našom stvarnom verzijom docker-mailservera i postojećom konfiguracijom Dovecota.
