## Korak 89 — ADR-089: Životni ciklus integracija i siguran opoziv pristupa

Sada definiramo **Integration Lifecycle Manager**, sustav koji upravlja povezivanjem, odobravanjem, nadzorom, privremenim zaustavljanjem i uklanjanjem integracija.

To nam je važno jer će novi Webmail moći surađivati s aplikacijama poput Stay.hr, ali svaka integracija mora imati jasno definirana prava i mogućnost trenutačnog isključivanja.

### 2. Statusi integracije

| Status | Značenje |
|---|---|
| `draft` | Integracija je konfigurirana, ali nije aktivna |
| `pending_approval` | Čeka administratorsko odobrenje |
| `active` | Može koristiti dodijeljene API ovlasti |
| `paused` | Privremeno zaustavljena obrada |
| `suspended` | Sigurnosno blokirana |
| `revoked` | Pristup trajno opozvan |
| `archived` | Neaktivna konfiguracija sa sačuvanom audit evidencijom |

Važno je razlikovati `paused` od `revoked`.

Privremena pauza može zaustaviti webhook isporuke bez poništavanja konfiguracije. Opoziv mora onemogućiti izdavanje novih tokena i korištenje postojećih vjerodajnica.

### 3. Što se događa kada isključimo integraciju?

Predlažem tri razine kontrole:

| Radnja | API pristup | Webhook isporuka | Konfiguracija |
|---|---|---|---|
| Pause delivery | Ostaje prema ovlastima | Zaustavljena | Sačuvana |
| Suspend integration | Blokiran | Zaustavljena | Sačuvana radi provjere |
| Revoke integration | Trajno opozvan | Zaustavljena | Arhivirana evidencija |

Kod suspenzije ili opoziva moramo blokirati i već izdane tokene. Samo brisanje `client_secret` nije dovoljno ako token još vrijedi.

Zato Authorization Service mora imati mogućnost hitne provjere opoziva ili kratkotrajnih tokena uz centralno blokiranje servisnog identiteta.

### 4. Što s događajima koji čekaju isporuku?

Ovo je važno za webhookove iz ADR-088.

Primjerice, Stay.hr integracija može imati 200 događaja na čekanju kada je privremeno zaustavimo.

Predlažem sljedeće ponašanje:

- `paused`: događaji se zadržavaju prema definiranoj politici retencije, ali se ne isporučuju.
- `suspended`: nema isporuke; prije ponovnog uključivanja provjerava se sigurnost.
- `revoked`: svi neisporučeni događaji trajno se isključuju iz isporuke toj integraciji, uz audit.
- Ponovna aktivacija ne smije nekontrolirano poslati veliki broj starih događaja.

Sama evidencija događaja ostaje pod zasebnim pravilima retencije i privatnosti. Opoziv integracije ne znači automatsko brisanje svih audit zapisa.

### 6. Sigurnosne kontrole

Predlažem da Integration Lifecycle Manager provodi periodičnu reviziju prava i prepoznaje integracije koje se dugo ne koriste.

Također treba pratiti neuobičajeno velik broj API zahtjeva, ponovljene neuspješne autentifikacije i pogreške u webhook isporuci.

Sigurnosno blokiranje kompromitirane integracije mora biti moguće odmah, bez čekanja redovitog administratorskog postupka.
