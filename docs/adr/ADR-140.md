## Korak 140 — ADR-140: Postfix Queue Manager, statusi dostave i administrativne intervencije

Sada projektiramo **Postfix Queue & Delivery Operations Center**.

Prema ADR-043 već smo odlučili da Webmail treba omogućiti nadzor Postfix reda i kontrolirane administrativne intervencije. U ovom koraku definiramo njegov detaljni model.

Cilj je da administrator vidi zašto poruka čeka dostavu i može sigurno reagirati, bez ručnog ulaska u Docker kontejner.

### 2. Razlika između slanja i isporuke

Ovo moramo jasno razlikovati.

| Stanje | Što zapravo znači |
|---|---|
| SMTP `accepted` | Postfix je prihvatio poruku |
| `queued` | Poruka čeka obradu |
| `active` | Postfix pokušava dostavu |
| `deferred` | Dostava je privremeno odgođena |
| `delivered` | Dostavni mehanizam prijavio je uspjeh za primatelja |
| `bounced` | Dostava je trajno odbijena |
| `expired` | Poruka je istekla prema Postfix politici |

Jedna poruka može imati više primatelja s različitim rezultatima dostave.

**Status dostave ne smijemo svesti na jedan `sent=true/false`.**

### 4. Koje administrativne operacije dopuštamo?

| Operacija | Razina kontrole |
|---|---|
| Pregled statusa queuea | RBAC |
| Pregled razloga odgode | RBAC + ograničavanje osjetljivih podataka |
| `flush` odgođenog reda | Step-up MFA + Dry Run |
| Ponovni pokušaj određenog Queue ID-a | Step-up MFA + validacija |
| `hold` poruke | Step-up MFA + audit |
| `release` poruke | Step-up MFA + audit |
| Uklanjanje pojedinačne poruke iz queuea | Izričita potvrda + visoki rizik |
| Masovno uklanjanje | Neovisno odobrenje + stroža kontrola |

Operacije se izvršavaju isključivo preko izoliranog Agenta.

Za uklanjanje poruke potrebno je jasno upozoriti da takav zahvat može spriječiti daljnju dostavu i da nije isto što i brisanje kopije iz korisničkog Sent foldera.

### 5. Queue ID i identitet slanja

Prema ADR-130 svako slanje koristi `send_operation_id`.

Postfix može dodijeliti vlastiti Queue ID, ali ne možemo pretpostaviti da je taj identifikator globalno ili trajno jedinstven kroz sve situacije.

Predlažem povezivanje:

`send_operation_id → SMTP pokušaj → Postfix instance + Queue ID + vrijeme`

Ta veza koristi se za dijagnostiku i audit, uz dodatne korelacijske metapodatke gdje su pouzdano dostupni.

Ako veza nije potvrđena, UI mora prikazati da je korelacija nepoznata, umjesto da nagađa.

### 6. Model podataka

Predlažem sljedeće tablice u modularnoj bazi:

| Tablica | Svrha |
|---|---|
| `system.postfix_queue_snapshots` | Vremenski ograničeni pregledi queuea |
| `system.postfix_queue_entries` | Metapodaci stavki reda |
| `system.delivery_attempts` | Zabilježeni pokušaji dostave |
| `system.queue_operations` | Administrativne operacije |
| `audit.queue_events` | Sigurnosni audit |

Ovdje ne pohranjujemo nepotrebne kopije sadržaja poruka.

Podatke o dostavi povezujemo s Postfix događajima samo kada postoji pouzdana osnova.

Ako queue stavka nestane prije operacije, to nije automatski pogreška. Poruka je možda upravo dostavljena, odbijena ili uklonjena drugim dopuštenim postupkom.

Zato Agent mora provjeriti stanje neposredno prije intervencije.

### 8. Zaštita od dvostrukog izvršavanja

Neke queue operacije imaju vanjske učinke, pa ponavljanje može biti opasno.

Primjerice, ponovni pokušaj dostave može dovesti do neželjenih posljedica ako nemamo točan status prethodne operacije.

Predlažem:

- Jedinstveni `operation_id`.
- Provjeru ciljnog Queue ID-a neposredno prije akcije.
- Zabranu automatskog ponavljanja neizvjesnih kritičnih operacija.
- Audit svih pokušaja.
- Poseban status `needs_review` ako rezultat nije pouzdano potvrđen.

### 9. Praćenje zdravlja dostave

Prema ADR-042 i ADR-043 pratimo:

| Metrika | Svrha |
|---|---|
| Ukupan queue | Opterećenje |
| Deferred queue | Problemi s dostavom |
| Starost najstarije poruke | Potencijalni zastoj |
| Broj bounceova | Trajne pogreške |
| Najčešći privremeni odgovori | Dijagnostika |
| Stanje DNS/DKIM/DMARC provjera | Kvaliteta konfiguracije |
| Promjene nakon administrativnih akcija | Validacija učinka |

Upozorenja se šalju prema pravilima Notification Centera, uz zaštitu privatnosti.
