## Korak 104 — ADR-104: Veliki privitci, sigurno dijeljenje i dostava datoteka

Sada definiramo kako Webmail može poslati datoteku koja je prevelika za klasičan e-mail privitak.

Prema ADR-036, maksimalna veličina MIME poruke u našem sustavu iznosi **50 MiB**. To uključuje MIME zaglavlja, kodiranje i sve privitke, pa datoteka veličine 50 MiB ne može nužno biti poslana kao privitak.

Predlažem mogućnost slanja **sigurne poveznice za preuzimanje**, umjesto umetanja velike datoteke u e-mail.

Datoteka ostaje izvan MIME poruke. Primatelj dobiva poruku s poveznicom, a samo preuzimanje obavlja se preko zaštićenog HTTPS sučelja.

### 2. Ponašanje pri slanju

| Veličina / stanje | Predloženo ponašanje |
|---|---|
| Privitak se uklapa u MIME limit | Standardno slanje |
| Ukupna MIME veličina prelazi limit | Ponuditi dijeljenje poveznicom |
| Antivirus otkrije prijetnju | Blokirati dijeljenje |
| Upload je prekinut | Omogućiti kontrolirani nastavak |
| Primatelj otvori poveznicu | Provjera valjanosti i pravila pristupa |
| Poveznica istekne | Odbiti preuzimanje |

Prije SMTP slanja datoteka mora biti uspješno pohranjena i dostupna kroz Download Gateway. U slučaju neuspjelog slanja sustav mora znati povezati datoteku s nacrtom ili omogućiti kontrolirano uklanjanje neiskorištenog dijeljenja.

### 3. Sigurnosna pravila poveznica

Predlažem sljedeće početne vrijednosti.

| Kontrola | Predložena politika |
|---|---|
| HTTPS | Obvezan |
| Token poveznice | Kriptografski nasumičan, dug i nepredvidljiv |
| Pohrana tokena | Samo hash tokena |
| Zadani rok isteka | 7 dana |
| Maksimalni rok | 30 dana |
| Lozinka za preuzimanje | Opcionalno |
| Ograničenje preuzimanja | Opcionalno |
| Opoziv | Odmah preko administratorskog ili korisničkog sučelja |
| Antivirus | Obvezan prije dostupnosti |
| Audit | Evidencija pristupa uz ograničenje osobnih podataka |

Ako se poveznica šalje bez dodatne autentifikacije, **svatko tko posjeduje valjani token može pristupiti datoteci**. Zato za osjetljive dokumente možemo zahtijevati zasebnu lozinku ili jednokratni kod koji se dostavlja drugim kanalom.

### 5. Upravljanje prostorom i kvotama

Budući da bi velike datoteke mogle brzo popuniti dedicated server, **Secure File Sharing Service mora imati vlastitu kvotu**, odvojenu od Dovecot mailbox kvote.

Predlažem da administratori mogu odrediti ograničenje po korisniku i domeni, maksimalnu veličinu datoteke i ukupno zauzeće prostora za dijeljenje.

Istekle i opozvane datoteke mogu se uklanjati prema zasebnoj politici retencije, nakon provjere postojećih obveza čuvanja i aktivnih referenci. Ovo ne smije brisati originalne privitke u Dovecotu.

### 6. Ograničenje javnog pristupa

Download Gateway treba biti odvojen od administrativnog API-ja, uz strogu provjeru tokena, zaštitu od brute-force pokušaja i ograničavanje prometa.

HTTP zahtjevi ne smiju omogućiti otkrivanje putanja na hostu ili pristup drugim Docker volumenima.

Za veće datoteke potreban je streaming i, gdje je sigurno izvedivo, podrška za nastavak prekinutog preuzimanja.

### 7. Posebno pitanje: gdje pohranjivati velike datoteke?

Imamo dvije arhitekturne mogućnosti:

- Vlastita šifrirana pohrana unutar Webmail infrastrukture.
- Integracija s postojećim Nextcloudom putem WebDAV-a i kontroliranih share linkova.

Obje mogu raditi, ali prva daje veću kontrolu nad pravilima, dok druga može smanjiti potrebu za razvojem zasebne pohrane i sučelja za dijeljenje datoteka.
