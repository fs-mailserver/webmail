### 2. Obvezni moduli prve verzije

| Modul | Minimalna funkcionalnost |
|---|---|
| Authentication | Passkey, lozinka + MFA, upravljanje sesijama |
| Korisnici | Super Admin, Admin, User |
| Mailboxi | Više mailboxa po korisniku, granularne ovlasti |
| IMAP | Sinkronizacija s UIDVALIDITY provjerama i sigurnim oporavkom |
| Inbox | Mape, poruke, nepročitano, oznake, brisanje |
| Composer | Nova poruka, Reply, Reply All, Forward, nacrti |
| SMTP | Slanje kroz Postfix i spremanje u IMAP Sent |
| Privitci | Siguran upload, antivirus, download |
| Search | Osnovni PostgreSQL Full-Text Search |
| Admin Console | Korisnici, povezivanje mailboxa, osnovna administracija |
| UI | Tri panela, Light/Dark, šest jezika, WCAG 2.2 AA |
| Operations | Monitoring, audit, backup i recovery provjere |

Sve osnovne funkcije moraju biti operativno zaokružene. Primjerice, nije dovoljno samo poslati e-mail: potrebno je provjeriti je li poruka spremljena u Sent, kako se ponaša pri mrežnom prekidu i kako spriječiti dvostruko slanje.

### 3. Što odgađamo?

Funkcionalnosti koje nisu nužne za početnu zamjenu SnappyMaila razvijamo u kasnijim fazama.

| Kasnija faza | Funkcionalnosti |
|---|---|
| Advanced Mail | Četiri napredna Inbox načina, Smart Search, složeni filtri, Snooze, Send Later, napredni preview |
| Productivity | Nextcloud File Picker, CalDAV, CardDAV, Tasks, Free/Busy |
| Workflow | Workflow Builder, Approval Center, predlošci, monitoring automatizacija |
| AI | Sažimanje, prijedlozi, AI klasifikacija i ostale opt-in mogućnosti |
| Flutter | Nativna mobilna aplikacija nakon stabilizacije web platforme |

Odgađanje nije odustajanje od potvrđenih ADR-ova. Znači da arhitektura mora omogućiti njihovo kasnije uvođenje bez nepotrebnog prepravljanja jezgre.

### 5. Kriteriji prihvaćanja Core verzije

Prije bilo kakvog prelaska sa SnappyMaila moramo moći potvrditi:

| Test | Kriterij |
|---|---|
| IMAP | Bez gubitka poruka i ispravna sinkronizacija stanja |
| SMTP | Nema dupliciranja poruka pri nejasnom rezultatu slanja |
| Mailbox ACL | Korisnik nikada ne vidi nedopuštenu poštu |
| Sessions/MFA | Sigurna prijava i opoziv sesija |
| Privitci | Antivirus, autorizacija i MIME zaštita |
| Restart | Oporavak bez korupcije podataka |
| PostgreSQL | Konzistentni indeksi i migracije |
| Backup | Uspješan test obnove |
| UI | Podržani preglednici, responzivnost, WCAG |
| Lokalizacija | Testirano svih šest jezika |
| Monitoring | Kritične pogreške su uočljive |
| Rollback | Dokumentiran i provjeren povratak na SnappyMail |

Posebno ćemo testirati rad na stvarnoj Docker infrastrukturi u izoliranom testnom okruženju. Produkcijski Dovecot mailboxi ne smiju se koristiti za destruktivne testove.

### 6. Potencijalni problem: previše funkcionalnosti u Core verziji

Trenutačni prijedlog prve verzije uključuje dosta naprednih sigurnosnih i infrastrukturnih komponenti.

To je prihvatljivo ako želimo odmah izraditi ozbiljnu produkcijsku zamjenu, ali treba razlikovati **obveznu sigurnost** od funkcionalnosti koje nisu nužne za početni rad.

Zato predlažem dva modela.
