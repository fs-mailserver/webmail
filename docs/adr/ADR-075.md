### 2. Scenariji koje trebamo testirati

| Scenarij | Što provjeravamo |
|---|---|
| Pad FastAPI kontejnera | Oporavak bez gubitka trajnih zadataka |
| Pad IMAP Workera | Nastavak od ispravnog checkpointa |
| Gubitak Redis podataka | Rekonstrukcija zadataka iz PostgreSQL-a |
| Oštećenje `webmail_db` | PITR obnova i integritet podataka |
| Gubitak lokalnih `.eml` kopija | Rekonstrukcija iz Dovecota |
| Oštećenje Dovecot pohrane | Obnova originalnih poruka iz backupa |
| Gubitak cijelog hosta | Obnova na čistoj infrastrukturi |
| Prekinuto Send Later slanje | Bez slijepog ponovnog slanja |
| Nedostupan Secrets Manager | Siguran prekid rada i kontrolirani oporavak |

Testovi koji koriste stvarne backup podatke moraju raditi u izoliranom okruženju, uz ograničen pristup i bez izlaznog slanja e-mailova stvarnim primateljima.

### 4. Učestalost testiranja

Predlažem sljedeći raspored:

| Test | Učestalost |
|---|---|
| Provjera integriteta backup datoteka | Svakodnevno |
| PostgreSQL PITR restore | Mjesečno |
| Dovecot restore uzorka poruka | Mjesečno |
| Oporavak pojedinačnih servisa | Mjesečno |
| Send Later / scheduler recovery | Prije relevantnog izdanja i kvartalno |
| Potpuna DR simulacija na novom hostu | Kvartalno |
| Provjera oporavka kriptografskih ključeva | Kvartalno |

Mjesečno testiranje obnove već smo usvojili u ADR-019. Ovdje ga proširujemo na cjelokupni DR postupak.

**Važno:** staging unutar produkcijskog Compose projekta, prema ADR-072, nije zamjena za test potpunog gubitka hosta. Taj scenarij zahtijeva neovisno testno okruženje.

### 5. Sigurnosne granice

Testni sustav ne smije automatski dobiti pristup produkcijskim Docker mrežama, SMTP odredištima ili stvarnim vanjskim API servisima.

Za posebno destruktivne simulacije kvarova — primjerice, namjerno rušenje produkcijske baze ili prekid mreže — nećemo koristiti produkciju.
