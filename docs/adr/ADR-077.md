## Korak 77 — ADR-077: Load testing, benchmark i kapacitetni pragovi

Sada definiramo kako ćemo **izmjeriti stvarne performanse Webmaila prije produkcije**.

Cilj nije samo dobiti brz Next.js frontend, nego dokazati da velik broj poruka, IMAP sinkronizacija, pretraga i AI obrada neće ugroziti postojeći mailserver.

### 2. Scenariji koje ćemo testirati

| Scenarij | Što mjerimo |
|---|---|
| Otvaranje Unified Inboxa | Brzinu prikaza indeksiranih razgovora |
| Istodobni korisnici | Latenciju pri rastu broja sesija |
| IMAP sinkronizacija | Opterećenje Dovecota i worker poola |
| Veliki mailbox | Paginaciju i historical backfill |
| Full-text pretraga | PostgreSQL upite i memoriju |
| Privitci do 50 MiB | Streaming i potrošnju resursa |
| Masovne IMAP operacije | Brzinu i djelomične neuspjehe |
| WebSocket / Push | Latenciju obavijesti |
| AI analiza | Backpressure i ograničenje troškova |
| Send Later | Točnost schedulera i sprječavanje duplikata |

### 3. Početni profili opterećenja

Predlažem tri razine, koje ćemo kasnije prilagoditi stvarnom broju korisnika i mailboxa.

| Profil | Istodobni korisnici | Ukupan broj poruka |
|---|---:|---:|
| Mali | 10 | 100.000 |
| Srednji | 50 | 1.000.000 |
| Veliki | 200 | 5.000.000 |

To su **testni profili, ne tvrdnja o trenutačnom kapacitetu servera**. Prije testiranja zabilježit ćemo raspoloživi CPU, RAM, disk I/O, veličine mailboxa i postojeće opterećenje ostalih servisa.

### 4. Kriteriji prolaza

Koristit ćemo ciljeve koje smo definirali u ADR-076.

| Operacija | Ciljani p95 |
|---|---:|
| Otvaranje indeksiranog Inboxa | 500 ms |
| Prikaz razgovora | 700 ms |
| Promjena pročitanosti | 500 ms |
| Pretraga pošiljatelja / naslova | 1 s |
| Full-text pretraga | 2 s |
| Command Palette | 150 ms |
| WebSocket događaj nakon detekcije | 1 s |

Za `mail.modify` operacije posebno ćemo mjeriti vrijeme potvrde iz Dovecota, a ne samo trenutačno ažuriranje sučelja.

Osim latencije, release neće proći ako se pojave nekontrolirani IMAP retry pokušaji, gubitak trajnih zadataka ili ugrožavanje mailserver dostave.

### 5. Zaštita produkcije tijekom testiranja

Prema ADR-072, staging se nalazi unutar istog Docker Compose projekta, ali je logički izoliran.

To **ne znači fizičku izolaciju resursa**.

Ako na istom dedicated serveru pokrenemo test od 200 korisnika i pet milijuna poruka, možemo opteretiti produkcijski PostgreSQL, diskove i Docker host čak i kada koristimo odvojene mreže i volumene.

Zato za velike stress testove preporučujem zaseban testni host ili drugo fizički odvojeno okruženje. Na produkcijskom hostu dopušteni bi bili samo ograničeni, unaprijed odobreni smoke i performance testovi.
