## 2. Credential Broker — odgovornosti

| Funkcija | Pravilo |
|---|---|
| Registracija tajne | Samo kontrolirano backend sučelje |
| Dohvat | Samo autorizirani servisni kontekst |
| Rotacija | Nova verzija + kontrolirano gašenje starih veza |
| Opoziv | Blokira nove pristupe tajni |
| Audit | Bilježi identitet operacije, ne vrijednost tajne |
| Cache | Kratkotrajan, strogo ograničen |
| Izvoz | Nije dopušten kroz obični API |
| Brisanje | Kontrolirano, uz provjeru referenci i retencije |

Važno: mailbox grant iz P1-04 ne daje korisniku pravo čitanja same tajne. On omogućuje autoriziranu operaciju koju backend obavlja koristeći odgovarajuću vjerodajnicu.

## 4. Predloženo Python sučelje

Ovo je **ugovorni pseudokod**, a ne kod za izvršavanje.

```python
class CredentialBroker(Protocol):
    async def acquire(
        self,
        credential_ref: str,
        operation_context: OperationContext,
    ) -> CredentialLease: ...

    async def rotate(
        self,
        credential_ref: str,
        rotation_request: RotationRequest,
    ) -> RotationResult: ...

    async def revoke(
        self,
        credential_ref: str,
        operation_context: OperationContext,
    ) -> None: ...
```

`CredentialLease` predstavlja kratkotrajno pravo uporabe tajne unutar pouzdanog backend konteksta.

Ne smije biti moguće serijalizirati ga u JSON odgovor ili ga ispisati u log.

**Važno:** niti sama anotacija `CredentialLease` niti Python tipovi ne predstavljaju sigurnosnu granicu. Pravo pristupa mora biti provjereno pri izvršavanju.

## 6. Izolirani SMTP adapter

SMTP je osjetljiviji jer izvršava vanjski učinak.

Predlažem da adapter ne nudi generičku metodu `send_anything()`.

Umjesto toga prima već autoriziranu, zamrznutu i validiranu poruku povezanu s jedinstvenom operacijom slanja.

```python
class SmtpAdapter(Protocol):
    async def submit(
        self,
        submission: FrozenSubmission,
        context: OperationContext,
    ) -> SubmissionResult: ...
```

`SubmissionResult` mora razlikovati:

- `accepted` — SMTP poslužitelj potvrdio je prihvat.
- `rejected` — dostava nije prihvaćena.
- `unknown` — rezultat nije moguće pouzdano utvrditi.

Za `unknown` je zabranjeno automatski ponovno slanje bez kontrolirane provjere.

Paket 1 ne izvodi stvarno SMTP slanje.

## 8. Sigurnosni kontekst operacije

Sve operacije moraju imati zajednički kontekst:

| Polje | Namjena |
|---|---|
| `actor_id` | Stvarni Webmail korisnik ili servis |
| `session_id` | Sesija, gdje je primjenjivo |
| `mailbox_ref` | Ciljni mailbox |
| `permission` | Zahtijevana ovlast |
| `operation_id` | Trajni identifikator operacije |
| `correlation_id` | Praćenje kroz servise |
| `approved_scope` | Odobreni opseg |
| `expires_at` | Istek autorizacije |

Kontekst mora kreirati pouzdani backend, ne klijent.

Ako se pravo opozove prije izvršavanja posla, worker mora ponovno provjeriti dopuštenje.

`MAIL_ADAPTER_MODE=mock`

`SMTP_ADAPTER_MODE=mock`

`ADMIN_AGENT_MODE=mock`

Izolirano okruženje mora imati i:

- Mrežnu zabranu pristupa produkcijskom mailserveru.
- Odvojene testne tajne.
- Provjeru konfiguracije pri pokretanju.

Factory mora odbiti podizanje servisa ako postoji nedopuštena kombinacija okruženja i adaptera.
