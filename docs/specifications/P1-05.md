## 2. Organizacija API-ja

Predlažem jedan javni API namespace:

`/api/v1`

Unutar njega razdvajamo domene.

| API modul | Namjena | Paket 1 |
|---|---|---|
| `/auth` | Prijava, Passkey, MFA, sesije | Da |
| `/users` | Korisnički profil i sigurnosne postavke | Da |
| `/access` | RBAC, mailbox grantovi, delegacije | Da |
| `/admin` | Simulirane privilegirane operacije | Da, mock |
| `/system` | Konfiguracija i status | Osnovno |
| `/mail` | Poruke, mape, IMAP operacije | Samo ugovori gdje su potrebni |
| `/search` | Pretraživanje poruka | Paket 2 |
| `/composer` | Nacrti i slanje | Paket 3 |
| `/integrations` | Vanjske integracije | Kasnije |

**Neaktivni moduli ne smiju prikazivati lažno funkcionalne endpointove.** U Paketu 1 stvarni IMAP i SMTP nisu dostupni.

## 3. Pydantic i OpenAPI

Predlažem sljedeća pravila:

- Pydantic modeli predstavljaju javne ulazne i izlazne podatke.
- SQLAlchemy modeli ne izlažu se izravno kroz API.
- Svaki endpoint ima dokumentirane odgovore i pogreške.
- OpenAPI dokument generira se deterministički.
- `operationId` mora biti stabilan.
- Promjene API ugovora provjeravaju se u CI-ju.
- TypeScript klijent nastaje iz točno određene verzije OpenAPI dokumenta.

Za razliku od ručno pisanih `fetch` poziva, generirani klijent daje provjerljive tipove i smanjuje rizik neslaganja frontenda i backenda.

### 4. API odgovor i pogreške

Predlažem koristiti JSON za poslovne odgovore i RFC 9457 Problem Details format za pogreške.

Primjer:

```json
{
  "type": "https://webmail.example.com/problems/permission-denied",
  "title": "Permission denied",
  "status": 403,
  "detail": "Operation is not permitted.",
  "instance": "/api/v1/access/grants",
  "request_id": "example-request-id"
}
```

Primjer je sintetički. `request_id` služi za dijagnostiku i ne sadrži tajne.

Za nepoznate ili nedopuštene mailbox resurse API ne smije nepotrebno otkrivati postoji li konkretan mailbox.

## 6. Idempotencija i verzioniranje promjena

Prema ADR-129, ADR-130 i ADR-133 uvodimo standardne mehanizme:

| Mehanizam | Namjena |
|---|---|
| `Idempotency-Key` | Sprječavanje dupliciranja logičke operacije |
| `If-Match` | Optimistic concurrency na verzioniranim resursima |
| `request_id` | Praćenje pojedinog HTTP zahtjeva |
| `operation_id` | Trajni identitet poslovne operacije |
| `correlation_id` | Povezivanje API-ja, workera i audita |

Idempotency ključ mora biti vezan uz korisnika, opseg operacije i sadržaj zahtjeva gdje je relevantno.

Ne smijemo automatski ponavljati SMTP slanje samo zato što je HTTP zahtjev završio timeoutom.

## 7. Paginacija i filtriranje

Za velike skupove podataka koristimo **keyset pagination**.

Primjer ugovora:

```json
{
  "items": [],
  "next_cursor": null,
  "has_more": false
}
```

Cursor mora biti neproziran i validiran na backendu, po potrebi vezan uz korisnika, opseg upita i verziju filtriranja.

Ne koristimo `OFFSET` kao primarni model za velike liste poruka.

## 8. WebSocket ugovor

WebSocket služi za obavijesti, ali ne zamjenjuje API.

Predloženi endpoint:

`/ws`

Primjer događaja:

```json
{
  "type": "mailbox.changed",
  "resource_ref": "opaque-mailbox-ref",
  "event_id": "example-event-id"
}
```

Nakon događaja Next.js poziva odgovarajući autorizirani API endpoint i osvježava podatke.

WebSocket mora imati provjeru Origina, sesije i prava na pretplaćeni resurs. Nakon opoziva sesije ili granta prekida se daljnja dostava zaštićenih događaja.

U Paketu 1 koristimo sintetičke događaje.

## 9. Dependency Injection i testiranje

Predlažem da FastAPI koristi dependency injection za:

| Dependency | Funkcija |
|---|---|
| `get_current_session` | Identitet i sesija |
| `require_permission` | RBAC i resursna ovlast |
| `get_db_session` | PostgreSQL transakcija |
| `get_credential_broker` | Upravljanje referencama na tajne |
| `get_mail_adapter` | Mock IMAP adapter |
| `get_smtp_adapter` | Mock SMTP adapter |
| `get_admin_agent` | Simulirani Agent |
| `get_audit_service` | Sigurnosna evidencija |

To omogućuje zamjenu testnih adaptera bez promjene poslovne logike.

Proizvodni adapteri ne smiju se aktivirati u Paketu 1.

## 10. Sigurnosna pravila API-ja

| Područje | Pravilo |
|---|---|
| Transport | HTTPS u odgovarajućim okruženjima |
| Cookies | HttpOnly, Secure, odgovarajući SameSite |
| CSRF | Obvezna zaštita state-changing zahtjeva |
| CORS | Samo eksplicitno odobreni origini |
| Rate limits | Login, recovery, administrativne operacije |
| Payload limits | Po endpointu, bez neograničenih tijela zahtjeva |
| Logging | Redakcija privatnih i tajnih podataka |
| API docs | Kontrolirana dostupnost u produkciji |
| Internal errors | Bez stack tracea u korisničkom odgovoru |
| Authorization | Default deny |
