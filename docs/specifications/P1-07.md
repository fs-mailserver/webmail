## 1. Cilj specifikacije

U Paketu 1 pripremamo temelje budućeg Webmail sučelja, ali još **ne razvijamo stvarni Inbox, Composer ni pristup porukama**.

Želimo da kasniji razvoj bude modularan i da ne moramo ponovno projektirati prijavu, navigaciju, sigurnost, višejezičnost ili povezivanje s FastAPI-jem.

Potvrđene tehnologije:

| Područje | Tehnologija |
|---|---|
| Frontend | Next.js + React + TypeScript |
| Stilovi | Tailwind CSS |
| UI komponente | shadcn/ui + Radix |
| API integracija | Generirani OpenAPI TypeScript klijent |
| Autentifikacija | WebAuthn / Passkeys, MFA |
| Sesije | Secure HttpOnly cookies |
| PWA | Service Worker, kontrolirani offline model |
| Pristupačnost | WCAG 2.2 AA |
| Jezici | HR, EN, ES, DE, IT, PT |

## 6. Sigurnosna integracija

Prema ADR-136 frontend mora primjenjivati:

| Kontrola | Pravilo |
|---|---|
| CSP | Nonce/hash, bez nepotrebnih iznimki |
| Trusted Types | Gdje je podržano |
| XSS | Bez nekontroliranog HTML renderiranja |
| CSRF | Za state-changing zahtjeve |
| Cookies | HttpOnly, Secure, odgovarajući SameSite |
| Session refresh | Kontrolirano prema backend politici |
| CORS | Samo dopušteni origini |
| Error handling | Bez izlaganja tajni |
| Logout | Server-side opoziv + best-effort cache cleanup |

Korisnički session token nije dostupan JavaScriptu.

Za autentifikacijske stranice predlažem onemogućiti trajno spremanje privatnih API odgovora.

## 7. PWA u Paketu 1

PWA arhitektura je potvrđena ADR-135, ali u Paketu 1 ne pohranjujemo e-mail poruke niti stvarne offline nacrte.

Predlažem samo:

- Osnovni Web App Manifest.
- Kontrolirani Service Worker za javni aplikacijski shell.
- Sigurnosna pravila cachea.
- Pripremu IndexedDB apstrakcije bez stvarnog mailbox sadržaja.
- Testove čišćenja lokalnih podataka nakon odjave.

Puna šifrirana offline funkcionalnost dolazi uz Inbox i Composer.

## 8. Šest jezika

Predlažem da od prvog paketa koristimo stabilne i18n ključeve.

| Kod | Jezik |
|---|---|
| `hr` | Hrvatski |
| `en` | Engleski |
| `es` | Španjolski |
| `de` | Njemački |
| `it` | Talijanski |
| `pt` | Portugalski |

Sve sistemske poruke, forme, validacije i sigurnosna upozorenja moraju imati prijevode.

Vremenske zone koristimo preko IANA identifikatora, a datume formatiramo prema jeziku korisnika.

## 9. Responsive i WCAG 2.2 AA

Temeljni layout mora raditi na desktopu, tabletu i mobilnom uređaju.

Obvezni testovi uključuju:

- Ispravnu navigaciju samo tipkovnicom.
- Vidljiv fokus.
- Oznake polja i razumljive greške.
- Kontrast i tekst pri povećanju.
- Pristupačne dijaloge i izbornike.
- Ispravno ponašanje Passkey i MFA formi.
- Lokalizaciju bez lomljenja layouta.

Ne smijemo tretirati automatski accessibility scan kao jedini dokaz WCAG usklađenosti.
