## 1. Arhitekturne granice

Odabiremo jedan monorepozitorij s tri izvršne aplikacije:

| Aplikacija | Tehnologija | Odgovornost |
|---|---|---|
| `apps/web` | Next.js + TypeScript | Korisničko sučelje, autentifikacijski tokovi, Admin Console |
| `apps/api` | FastAPI + Python | Autorizacija, poslovna logika, OpenAPI, server-side sesije |
| `apps/worker` | Celery + Python | Asinkroni zadaci i kontrolirana obrada poslova |

**Pravilo:** Next.js ne smije izravno pristupati PostgreSQL-u, Redis redovima, Dovecotu ili Postfixu. Poslovne operacije idu kroz autorizirani FastAPI sloj.

Celery worker također koristi `webmail_core`, ali ne uvozi FastAPI route module.

| Smjer ovisnosti | Dopušteno |
|---|---|
| Web → API preko generiranog klijenta | Da |
| API → `webmail_core` | Da |
| Worker → `webmail_core` | Da |
| `webmail_core` → FastAPI routes | Ne |
| `webmail_core` → Next.js | Ne |
| Web → PostgreSQL | Ne |
| Web → IMAP/SMTP | Ne |
| Testni adapter → stvarni mailserver | Ne u Paketu 1 |

Ako poslovni modul treba vanjski sustav, koristi definirano sučelje adaptera i dependency injection.

## 4. Vlasništvo nad podacima

Svaki modul mora imati jasno definirane granice.

| Modul | Vlastiti podaci / odgovornost |
|---|---|
| `identity` | Korisnici, Passkeys, MFA, sesije |
| `access` | RBAC, mailbox grantovi, delegacije |
| `credentials` | Reference na tajne, rotacija, pristup |
| `mail` | Sučelja IMAP/SMTP adaptera |
| `admin` | Model administrativnih operacija i simulirani Agent |
| `audit` | Sigurnosni događaji |
| `system` | Konfiguracija, healthchecks, feature flags |

Moduli ne smiju proizvoljno mijenjati tuđe tablice. Međusobne operacije moraju prolaziti kroz javna Python sučelja modula.

Za PostgreSQL zadržavamo jednu migracijsku povijest Alembica i prethodno potvrđene sheme.

## 5. Pravila za API i frontend

Prema ADR-133:

- API je verzioniran pod `/api/v1`.
- Pydantic modeli definiraju ulazne i izlazne ugovore.
- TypeScript klijent generira se iz OpenAPI specifikacije.
- Autorizacija se provjerava na backendu za svaki zahtjev.
- Frontend ne smije zaobići generirani API klijent proizvoljnim pozivima privilegiranih endpointa.
- WebSocket događaji služe za obavijesti i naknadno autorizirano osvježavanje, a ne za zaobilaženje API autorizacije.

Frontend u Paketu 1 sadrži samo aplikacijski kostur, login i osnovni sigurnosni layout. Stvarni Inbox dolazi u Paketu 3.

## 6. Konfiguracija i tajne

Predlažem tri razine konfiguracije:

| Razina | Sadržaj |
|---|---|
| Build-time | Javni parametri aplikacije |
| Runtime | URL-ovi servisa, ograničenja, feature flags |
| Secret Store | Kriptografske tajne, servisne vjerodajnice |

`NEXT_PUBLIC_*` vrijednosti nikad ne smiju sadržavati tajne.

U Paketu 1 koristimo isključivo testne vrijednosti. Produkcijske IMAP/SMTP lozinke, tokeni ili ključevi ne smiju biti prisutni u lokalnom developmentu i CI-ju.
